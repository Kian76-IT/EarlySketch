# EarlySketch – Progressive Sketch Recognition

## 1. Project Overview

EarlySketch is a sketch image preprocessing project designed to investigate how the level of drawing completion affects image recognition performance using a pretrained Vision Transformer (ViT), specifically DINOv2.

The project uses the **Google Quick, Draw! Dataset** as its primary data source. Each drawing consists of a sequence of strokes that represent the chronological process of creating a sketch.

Instead of using only fully completed drawings, EarlySketch generates multiple versions of each drawing at different completion levels:

- 20%
- 40%
- 60%
- 80%
- 100%

These progressive sketches are generated by preserving the original stroke order. The resulting images are rasterized into RGB images with a resolution of 224 × 224 pixels.

The current development scope focuses on dataset preparation, progressive sketch generation, image preprocessing, and dataset splitting. Model training and evaluation are separate subsequent stages.

## 2. Project Objectives

The main objectives of this project are:

1. Explore and prepare the Google Quick, Draw! Dataset.
2. Generate progressive sketches based on drawing completion percentages.
3. Preserve the chronological order of the original drawing strokes.
4. Convert stroke-based drawings into RGB images with a consistent resolution.
5. Divide the dataset into training, validation, and testing subsets.
6. Prepare a structured dataset for subsequent experiments using DINOv2.

## 3. Dataset

### Google Quick, Draw! Dataset

EarlySketch uses the Google Quick, Draw! Dataset, which contains drawings represented as sequences of pen strokes.

Each drawing contains information such as:

- `key_id`: Unique identifier of a drawing.
- `word`: Drawing category.
- `recognized`: Indicates whether the drawing was recognized by the original Quick, Draw! system.
- `timestamp`: Drawing creation timestamp.
- `drawing`: Collection of strokes representing the drawing.

Each stroke contains coordinate sequences:

- X coordinates
- Y coordinates
- Timestamp coordinates

The original stroke sequence is important because EarlySketch uses it to generate progressive sketches.

## 4. Methodology: Pure Stroke-Based Approach

### What is Pure Stroke-Based?

Pure Stroke-Based is an approach that generates incomplete sketches by selecting the first N strokes from the original drawing while preserving their chronological order.

A drawing is not divided based on individual points. Instead, the selection is performed at the stroke level.

For example, consider an original drawing containing 10 strokes:

| Completion | Selected strokes |
|---|---:|
| 20% | 2 |
| 40% | 4 |
| 60% | 6 |
| 80% | 8 |
| 100% | 10 |

The selected strokes are always taken from the beginning of the original sequence.

### Why Pure Stroke-Based?

EarlySketch uses Pure Stroke-Based for several reasons:

**1. Preserves the original drawing process**

Each stroke is generated in chronological order. Therefore, the progressive sketch represents the original sequence in which the drawing was created.

**2. Avoids artificial stroke combinations**

The method does not randomly select or rearrange strokes. This prevents the generation of sketches that do not follow the original drawing process.

**3. Provides consistent completion levels**

Each completion level is determined by the proportion of selected strokes relative to the total number of strokes.

**4. Supports controlled experiments**

Using the same original drawing across five completion levels allows subsequent experiments to investigate how different amounts of drawing information affect recognition performance.

### Completion Calculation

The number of selected strokes is calculated using:

```python
selected_strokes = floor(
    total_strokes * percentage / 100
)

selected_strokes = max(1, selected_strokes)
```

The selected strokes are then obtained using:

```python
partial_drawing = drawing[:selected_strokes]
```

The minimum value of one ensures that a non-empty drawing always retains at least one stroke.

**Important limitation:** Completion percentage represents the proportion of strokes, not the visual or semantic completeness of an object. Drawings with very few strokes may produce identical results at multiple completion levels because of integer rounding.

## 6. File Descriptions

### A. `src/`

This directory contains the main Python modules responsible for dataset preparation and image processing.

| File | Function |
|---|---|
| `dataset_sampler.py` | Handles the selection and sampling of original drawings from the Quick, Draw! dataset. |
| `progressive_generator.py` | Generates partial sketches based on predefined completion levels while preserving the original stroke order. |
| `rasterizer.py` | Converts stroke-coordinate data into raster images using Pillow. |
| `image_preprocessor.py` | Provides image preprocessing and validation utilities, including RGB format and image dimension checks. |

#### `progressive_generator.py`

This module implements the Pure Stroke-Based method.

Its main function is:

```python
generate_partial_sketch(drawing, percentage)
```

The function receives an original drawing and a completion percentage, then returns the first N strokes based on the selected completion level.

#### `rasterizer.py`

This module converts stroke data into image representations.

Its main functions are:

- `get_valid_strokes()`: Filters invalid stroke structures.
- `render_sketch()`: Renders stroke coordinates into an RGB image.
- `save_sketch()`: Saves the rendered image as a PNG file.

The rasterizer uses a white background and black drawing strokes.

It also supports `reference_drawing` to maintain consistent scale and position across different completion levels of the same original drawing.

This ensures that changes between progressive versions are caused by the addition of strokes rather than changes in image scaling.

#### `image_preprocessor.py`

This module provides utilities for handling and validating processed images.

It is intended to ensure that images meet the required input specifications, including RGB color mode and 224 × 224 resolution.

### B. `scripts/`

#### `run_preprocessing.py`

This is the main execution script for the preprocessing pipeline.

Its responsibilities include:

1. Loading train, validation, and test metadata.
2. Reading the corresponding original drawings from NDJSON files.
3. Generating five progressive versions of each drawing.
4. Converting each partial drawing into an RGB image.
5. Saving images into their corresponding dataset split and completion-level directories.
6. Validating the saved images.
7. Generating `processed_metadata.csv`.

This script allows the entire preprocessing pipeline to be executed without manually processing each drawing.

### C. `notebooks/`

The notebooks are used for exploration, visualization, experimentation, and monitoring the preprocessing process.

| Notebook | Function |
|---|---|
| `01_dataset_exploration.ipynb` | Explores the original dataset, examines its structure, checks stroke information, and visualizes sample drawings. |
| `02_dataset_splitting.ipynb` | Divides original drawings into training, validation, and testing subsets. |
| `03_progressive_visualization.ipynb` | Demonstrates how a drawing develops from 20% to 100% completion. |
| `04_dataset_preprocessing.ipynb` | Runs the preprocessing pipeline, displays processed images, and validates the generated dataset. |

### D. `data/`

This directory stores the original dataset, split metadata, and processed images.

#### `data/sampled/`

Contains the sampled original Quick, Draw! NDJSON files.

Each file represents one drawing category.

#### `data/splits/`

Contains the metadata used to divide the original drawings into three subsets:

- `train.csv`
- `validation.csv`
- `test.csv`

#### `data/processed/`

Contains the generated progressive sketch images.

Each split contains five subdirectories representing the five completion levels.

`processed_metadata.csv` stores information about generated images, including drawing identifiers, categories, completion levels, stroke counts, and image paths.

### E. `outputs/`

Stores additional project outputs.

- `reports/`: Dataset statistics and preprocessing reports.
- `visualizations/`: Saved progressive sketch visualizations and other figures.

## 7. Program Workflow

The EarlySketch preprocessing pipeline follows these stages:

### Stage 1: Dataset Sampling

Original drawings are collected from the Google Quick, Draw! Dataset.

The selected dataset contains 10 categories with 500 drawings per category.

The sampled NDJSON files are stored in:

```text
data/sampled/
```

### Stage 2: Dataset Exploration

The original dataset is examined to understand its structure and characteristics.

The exploration includes:

- Number of drawings per category.
- Number of strokes per drawing.
- Number of points per stroke.
- Drawing structure and validity.
- Sample drawing visualization.

### Stage 3: Dataset Splitting

Original drawings are divided into:

- 70% Training
- 15% Validation
- 15% Testing

The splitting process is performed before generating progressive versions.

This is important to prevent data leakage. All completion variants belonging to the same original drawing must remain in the same split.

### Stage 4: Progressive Sketch Generation

Each original drawing is processed using Pure Stroke-Based.

Five progressive versions are generated:

```text
Original Drawing
      |
      ├── 20%
      ├── 40%
      ├── 60%
      ├── 80%
      └── 100%
```

Only the first N strokes are selected, and their original chronological order is maintained.

### Stage 5: Rasterization and Image Preprocessing

Each progressive drawing is converted into a raster image.

The rasterization process includes:

1. Creating a white RGB canvas.
2. Extracting valid X and Y coordinates.
3. Calculating drawing boundaries.
4. Scaling and centering the drawing.
5. Rendering strokes using black lines.
6. Saving the result as a PNG image.

The final image specifications are:

| Property | Value |
|---|---|
| Format | PNG |
| Color mode | RGB |
| Resolution | 224 × 224 |
| Background | White |
| Stroke color | Black |

A fixed reference drawing is used to maintain consistent scale and position across completion levels.

### Stage 6: Dataset Storage

Generated images are saved according to their original dataset split and completion percentage.

For example:

```text
data/processed/train/20/
data/processed/train/40/
data/processed/train/60/
data/processed/train/80/
data/processed/train/100/
```

The same structure is used for validation and test datasets.

### Stage 7: Dataset Validation

The processed dataset is checked to ensure:

- All expected images exist.
- Images use RGB color mode.
- Image dimensions are 224 × 224.
- Images are stored in the correct split.
- Completion-level metadata is recorded correctly.
